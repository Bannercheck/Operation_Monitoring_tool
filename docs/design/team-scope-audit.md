# Team-scope security audit — API routers

Status: audit, 2026-10-15. Auditor view: a member of **Team A** must never read or change **Team B**'s data.
Method: a private instance (API `:8094`, receiver `:8694`, fresh DB) seeded with two teams (A owns `a-*`, B owns `b-*`),
a custom non-`scope.all` role `team_power` (= `operator` + `sys.notify`), a Team-A user (**alice**), a Team-B user (**bob**),
and a **team-less** user (**carol**). Team-B objects were created by bob (dataset, action, note, notify recipient/rule,
threshold policy, business flow, RUM app, source), plus B hosts, agents, inventory and live log lines carrying the marker
`BSECRET`, B host names (`b-web-01`/`b-db-01`), B IPs (`10.2.0.*`) and a recipient phone number. Alice then called every
read endpoint and every write endpoint against B's objects. Probes and raw results:
`/tmp/claude-0/-home-user-ollama-audit/bfc57f50-78ff-592d-9391-a77388507cf6/scratchpad/audit/{probe_reads.py,probe_writes.py,reads.json,writes.json}`.

## Verdict

Host-scope (`user_scope` / `Scope.allows`) is applied **only on the routers that were explicitly wired for it** —
`live/*`, `range/*`, `inventory` (list/discovered only), `agents` (list only), `anomalies`, `thresholds` (overview/state/preview only),
`apm`/`rum`/`flows` (live feed only), `map` (live only). **Most of the other routers have no scope at all**: `datasets`,
`actions`, `playbook`, `knowledge`, `memory`, `notify`, `sources`, `grok`, `llm`, `itsm` never import `user_scope`. On the
scoped routers the filter is also applied **inconsistently**: the list is scoped but the by-id GET, the CSV export or the
agent roster embedded in a payload are not. Every write endpoint is guarded by a **global** permission (`act.inventory`,
`act.connect`, `act.anomaly`, `sys.notify`, `act.rum`, `act.sources`, `act.scan`, `page.data`) with **no object-level team
check**, so any user holding the permission edits or deletes any team's object by id.

Good news: **RBAC privilege-escalation is solid** — a non-admin cannot grant a permission it does not hold (`PUT /roles/*`
→ 403) and cannot edit the `admin` role; self-role/self-status change is blocked; `inventory/promote` is correctly scoped.
The gaps below are **horizontal** (team-to-team), not vertical.

Severity: **Critical** = raw cross-team data (log bodies, PII) readable by any authenticated user; **High** = cross-team
business data or host inventory/security posture readable or destructible; **Medium** = metadata/definitions leak or
requires an id/second permission; **Low** = minor metadata or config.

## What is already correct (no change needed)

- `live/*` and `range/*` log/metric/SLO/session/latency/group views: scoped via `_hp`/`_hx` → `Scope.host_filter`; `/live/events?host=b-db-01`, `/live/lines`, `/live/discoveries` all return empty for alice.
- `inventory` list + `discovered`, `agents` list, `anomalies` list + stats + by-id (`_mine` 404s), `thresholds` overview/state/preview, `apm` live services/topology/hosts (`/apm/hosts/b-db-01/integrations` → 404), `rum` apps/overview/sessions/session (`_apps_ok`), `flows` funnel **items**, `map?dataset=live`, `bizflow suggest`, `apm/exceptions`: all scope-filtered.
- RBAC vertical controls: `PUT /roles/{name}` rejects granting unheld perms (403) and editing `admin`; `PATCH /users/{id}` blocks self-role/self-status and non-admins managing admins; `inventory/promote` rejects hosts outside scope (403).

## Root-cause summary for the fix pass (not applied here)

1. **No ownership model for non-host objects.** Datasets, actions, playbook entries, KB/memory rows, notify recipients/rules/groups, sources, flows and RUM apps have no team column, so they cannot be scoped. The single biggest fix is an `owner_team` (or contributing-team set) on these tables, populated from the creating user's team, with a shared/global sentinel for intentionally-shared rows.
2. **Scope applied per-handler, not centrally.** Where scope exists it is hand-written on some handlers of a router and forgotten on siblings (list vs. export vs. by-id vs. the embedded `agents` map). A shared dependency/helper that every read returns through, plus an object-level `require_team(obj)` for every write, would close the by-id / export / mutate gaps uniformly.
3. **Writes are permission-gated but not object-gated.** Holding `act.*`/`sys.notify`/`page.data` lets a user mutate any team's object by id. Each mutate needs the same team check as the matching read.
